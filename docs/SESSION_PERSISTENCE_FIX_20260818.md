# إصلاح بقاء جلسة الدخول — 2026-08-18

## السبب

كانت الجلسة تعتمد على إعداد secure مشتق مباشرة من `NODE_ENV`. عند تشغيل `next start` في وضع production على HTTP المحلي، قد تُنشأ كوكي secure لا يرسلها المتصفح عبر HTTP. كما كان `DashboardLayout` يعيد توجيه المستخدم إلى `/login` عند وجود أي `data.error` من `/api/user`، بما في ذلك أخطاء عابرة في الشبكة أو Turso، وليس فقط عند انتهاء الجلسة فعليًا.

## الإصلاح

تم تحديث `src/lib/auth.ts` لتثبيت إعدادات الكوكي صراحةً: `httpOnly`، و`sameSite: lax`، و`path: /`، ومدة 30 يومًا. يبقى secure مفعّلًا تلقائيًا في production، مع خيار `SESSION_COOKIE_SECURE=0` للاختبار المحلي عبر HTTP فقط. تمت إضافة تحقق واضح من وجود `SESSION_SECRET` بطول لا يقل عن 32 محرفًا.

تم تحديث `src/app/components/DashboardLayout.tsx` ليستخدم `credentials: include`، ولا يعيد التوجيه إلا عند HTTP 401. أما 5xx أو فشل الشبكة المؤقت فيحافظ على حالة العرض الحالية ولا يظهر كتسجيل خروج.

تمت إضافة `SESSION_COOKIE_SECURE=0` إلى `.env.local` المحلي فقط. يجب ضبطه على `1` أو تركه غير مضبوط عند النشر خلف HTTPS.

## نتائج الاختبار

| الاختبار | النتيجة |
|---|---|
| تسجيل الدخول | HTTP 200 |
| طلب `/api/user` الأول بعد الدخول | HTTP 200 مع بيانات user |
| طلب `/api/user` المتكرر بنفس الكوكي | HTTP 200 مع بيانات user |
| كوكي الجلسة | HttpOnly وSameSite=Lax موجودان |
| تسجيل الخروج اليدوي | HTTP 200 |
| طلب `/api/user` بعد الخروج اليدوي | HTTP 401 كما هو متوقع |
| `pnpm run build` | ناجح |

لم يتم تنفيذ أي طلب خدمة مدفوع أو أي تغيير على بيانات الخدمات أثناء الاختبار.
