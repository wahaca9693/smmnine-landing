# إصلاح دخول حساب الإدارة — 2026-08-17

## السبب

كانت قاعدة Turso متصلة، لكن جدول `users` كان فارغًا؛ لذلك لم يكن هناك حساب إداري يستطيع مسار `/api/auth/login` العثور عليه. لم يكن الخلل من تصميم صفحة الدخول أو من صلاحية مسار الإدارة.

## الإجراء

تم تشغيل سكربت المشروع الرسمي `scripts/seed.ts` بعد تحميل متغيرات Turso، فتم إنشاء الحساب الإداري الافتراضي وحساب الاختبار وخيارات الدفع الموجودة في seed. لم يتم إنشاء طلب خدمة أو تنفيذ خصم من أي محفظة.

## التحقق

- حساب `admin` موجود بدور `admin` وحالته `active` وغير محظورة.
- اختبار `POST /api/auth/login` محليًا أعاد `HTTP 200` وجلسة صالحة.
- اختبار تسجيل الدخول عبر الرابط العام أعاد `HTTP 200` وأرجع الدور `admin`.
- صفحة `/admin` عبر الرابط العام أعادت `HTTP 200` بعد إرسال جلسة الإدارة.
- `/api/health` أعاد `ok: true`.

## بيانات اختبار الحساب المزروع

اسم المستخدم: `admin`

كلمة المرور: تُضبط خارج المستودع عبر متغير بيئة أو مدير أسرار، ولا تُحفظ في التوثيق أو GitHub.

يجب استخدام كلمة مرور قوية وفريدة في كل بيئة، وعدم مشاركة بيانات حساب الإدارة أو وضعها في ملفات المشروع.

## ملاحظة تشغيلية

في أي قاعدة Turso جديدة وفارغة، يجب تشغيل:

```bash
set -a
. ./.env.local
set +a
pnpm exec tsx scripts/seed.ts
```

لا ينبغي تشغيل seed تلقائيًا في كل إقلاع إنتاجي، حتى لا تُنشأ بيانات افتراضية دون قصد.
