# smmnine — التوثيق الشامل للمشروع

> منصة SMM احترافية لإدارة خدمات التسويق عبر وسائل التواصل الاجتماعي، مبنية بتصميم **Royal Gold**، ومتصلة بقاعدة Turso/libSQL، مع API v2 للمستخدمين وإدارة مزودي الخدمات وإعدادات شحن العملات الرقمية حسب العملة والشبكة.

## 1. نبذة تنفيذية

تم تطوير smmnine من لوحة خدمات بسيطة إلى منصة متعددة الأجزاء تشمل واجهة مستخدم للمشتركين، لوحة إدارة، كتالوج خدمات مركزي، نظام مزودين خارجيين، محفظة ورصيد، API v2، وصفحات دعم وإيداع. يعتمد المشروع على Next.js App Router وReact وTypeScript، بينما تُحفظ البيانات التشغيلية في Turso عبر `@libsql/client`، وتُدار الجلسات باستخدام `iron-session`.

النسخة الحالية الموثقة موجودة على فرع النشر:

`deploy/royal-gold-crypto-turso-20260817`

وقد رُفع الفرع نفسه إلى المستودع الأساسي ونسخة النسخ الاحتياطي. لا يحتوي Git على `.env.local` أو رموز Turso أو مفاتيح NOWPayments أو عناوين المحافظ الفعلية؛ عناوين الشبكات تُقرأ من إعدادات قاعدة البيانات وقت التشغيل.

## 3. الهوية البصرية Royal Gold

التصميم يعتمد على ذهبيات ثابتة ومتدرجة بدل الخلفيات الشفافة الثقيلة. تم توحيد الأزرار والبطاقات والحدود وعناصر الحالة حول متغيرات CSS مخصصة، مع الحفاظ على تباين مناسب في الوضع الداكن.

يشمل النظام البصري ما يلي:

- تدرجات ذهبية للأزرار الرئيسية وعناصر التركيز.
- بطاقات ثابتة بلون السطح بدل glassmorphism المبالغ فيه.
- حدود ذهبية منخفضة الشدة لتحديد الأقسام دون إرباك.
- أحجام أزرار طبيعية ومناسبة للموبايل، وليست ممتدة أو ضخمة بلا حاجة.
- حالات واضحة للتحميل والنجاح والتحذير والخطأ.
- دعم اللغة العربية والإنجليزية مع واجهة قابلة للتوسع.
- تجاوب مخصص لعرض 390px مع معالجة القائمة السفلية والتنقل.
- شعارات مستقلة لـ BTC وBNB وUSDT وأسماء الشبكات بجانب كل خيار.

## 5. طبقة قاعدة البيانات Turso

يوجد اتصال مركزي في `src/lib/db.ts`. يمنع الكود استخدام قاعدة SQLite المحلية في الإنتاج عند توفر إعدادات Turso، بينما يسمح باستخدام SQLite محلية للاختبارات فقط عند ضبط `USE_LOCAL_DB=1` محليًا.

تتضمن الجداول التشغيلية الأساسية المستخدمين والجلسات والخدمات والطلبات والمعاملات والإيداعات المشفرة وطرق الدفع ومزودي الخدمات وخدمات المزودين ومفاتيح API والتذاكر والإشعارات وإعدادات الموقع والثيم.

تُنفذ عمليات الإيداع الحساسة بأسلوب idempotent في مسار اعتماد إيداعات العملات الرقمية حتى لا يُضاف الرصيد مرتين عند إعادة إرسال نفس الإشعار أو مراجعة نفس السجل.

## 6. كتالوج الخدمات والمزودون

تم إنشاء عميل موحد في `src/lib/providers.ts` لتجنب تكرار منطق استدعاء مزودي SMM. تدعم لوحة الإدارة إضافة مزود خارجي، تخزين نوعه ومفتاحه في الخادم، جلب خدماته، ثم اختيار الخدمات التي ستظهر للمستخدمين.

يدعم النظام:

- إظهار أو إخفاء الخدمة فورًا.
- تعديل اسم الخدمة دون تغيير المعرّف الداخلي.
- تعديل السعر وهامش الربح.
- ربط الخدمة بخدمة مزود خارجي.
- فلترة مزودي الخدمات النشطين فقط.
- عزل مفاتيح المزودين عن الواجهة العامة.
- انعكاس التعديلات على واجهة المستخدم وAPI v2 عبر القراءة من Turso.

## 7. API v2 للمستخدمين

المسار الأساسي هو `/api/v2`. كل مستخدم يستطيع الحصول على مفتاح API خاص به من صفحة `/api-access`. المفتاح يُستخدم من موقع أو Bot أو لوحة خارجية، ولا ينبغي وضعه في كود متصفح عام.

يدعم API v2 العمليات القياسية مثل:

| العملية | السلوك |
|---|---|
| `balance` | قراءة رصيد محفظة المستخدم |
| `services` | قراءة الخدمات النشطة والأسعار الحالية |
| `add` | إنشاء طلب من رصيد المستخدم بعد التحقق |
| `status` | قراءة حالة طلب يخص المستخدم نفسه |
|

يتم الخصم من محفظة صاحب مفتاح API، وليس من رصيد الإدارة. إذا كان الرصيد غير كافٍ يُرفض الطلب قبل استدعاء المزود. لا تُنفذ اختبارات API الحالية طلبات خدمة حقيقية مدفوعة.

## 8. إصلاحات مسارات API

تم إصلاح مسار `/api/orders/create` لقراءة الخدمات من Turso ودعم خدمات Follower والمزودين مع حساب السعر والخصم والاسترجاع الذري الآمن.

تم توحيد `/api/v2` مع عميل المزود المشترك والتحقق من المزود النشط والخصم المشروط من محفظة المستخدم.

تم تعطيل المسارات القديمة التالية بإرجاع HTTP 410 حتى لا تُستخدم مسارات قديمة أو غير متوافقة:

- `/api/create-order`
- `/api/balance`
- `/api/order-status`
- `/api/cancel`
- `/api/refill`

المسارات العامة الحساسة تستخدم رؤوس `no-store` لمنع التخزين المؤقت لمعلومات الرصيد والخدمات والإيداعات.

## 9. الشحن والعملات الرقمية

تُعرض خيارات الإيداع من جدول `payment_methods` في Turso. يحتوي إعداد كل طريقة على العملة والشبكة والعنوان العام، وتعرض واجهة `/deposit` اسم الشبكة والعنوان ونسخة QR مبنية من القيمة الرسمية القادمة من قاعدة البيانات.

الشبكات التي تم إعداد عناوينها العامة لها:

| العملة | الشبكة |
|---|---|
| BTC | Bitcoin SegWit |
| USDT | BNB Smart Chain / BEP20 |
| USDT | Tron / TRC20 |
| BNB | BNB Smart Chain / BEP20 |
| USDT | Ethereum / ERC20 |
| USDT | Polygon |
| USDT | X Layer |

تتحقق الواجهة والمسارات الخلفية من تطابق العملة والشبكة والعنوان الرسمي المخزن في Turso. لا يُقبل عنوان يرسله العميل إذا لم يطابق إعداد الإدارة. كما تعرض الواجهة تحذيرًا صريحًا من إرسال عملة على شبكة خاطئة.

> **الحالة التشغيلية:** تم تعطيل الاعتماد الآلي للإيداعات حاليًا (`is_auto=0`) إلى أن يكتمل ربط NOWPayments بمفاتيح جديدة غير مكشوفة وWebhook IPN موقّع. لذلك لا ينبغي وصف النسخة الحالية بأنها شحن تلقائي إنتاجي كامل.

## 10. NOWPayments وخطة التفعيل الآمن

خطة التكامل الإنتاجي تتطلب متغيري بيئة محميين في Vercel:

- `NOWPAYMENTS_API_KEY`
- `NOWPAYMENTS_IPN_SECRET`

يجب تدوير المفتاحين اللذين ظهرا سابقًا في المحادثة قبل أي تشغيل إنتاجي. عند اكتمال التكامل، يجب أن ينشئ المسار فاتورة مرتبطة بـ`userId` و`depositId`، وأن يتحقق من توقيع HMAC-SHA512، وأن يضيف الرصيد مرة واحدة فقط عند وصول الحالة النهائية الصحيحة. لا تُحفظ المفاتيح في Git ولا في الواجهة.

## 11. المزامنة الحية

تمت إضافة `useLiveRefresh` لإعادة جلب البيانات عند عودة الصفحة للتركيز وبفاصل زمني محدد. يستخدم في الخدمات والرصيد والثيم وصفحة الطلب الجديد، مع إيقاف المؤقت عند عدم رؤية الصفحة لتقليل الطلبات غير الضرورية.

الهدف هو أن تنعكس تعديلات الإدارة على الخدمات والأسعار والإخفاء والإظهار دون الحاجة إلى إعادة تشغيل التطبيق أو الاعتماد على cache قديم.

## 12. الأمان

لا تُرفع الملفات التالية إلى Git:

- `.env.local` وملفات البيئة الأخرى.
- `TURSO_AUTH_TOKEN`.
- `SESSION_SECRET` الحقيقي.
- مفاتيح NOWPayments وIPN.
- مفاتيح مزودي الخدمات.
- عناوين محافظ يتم وضعها في إعدادات تشغيل سرية بدلًا من كود الواجهة.

توجد حماية من عدم المصادقة، وفصل واضح بين مسارات المستخدم ومسارات الإدارة، وتحقق من ownership عند قراءة الطلبات عبر API، ومنع الاعتماد المكرر للإيداعات.

## 13. الاختبارات المنفذة

تم تنفيذ الفحوصات التالية دون طلب خدمة مدفوعة أو تحويل أموال حقيقي:

| الفحص | النتيجة |
|---|---|
| `pnpm exec tsc --noEmit` | ناجح |
| `pnpm build` | ناجح |
| `/api/orders/create` دون جلسة | HTTP 401 |

| قراءة طرق الدفع من Turso | ناجحة، مع العملة والشبكة والعنوان الرسمي |
| فحص QR للعناوين العامة | تم فك الرموز مباشرة ومطابقة الشبكات بصريًا |
